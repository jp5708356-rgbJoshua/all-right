# 第3b轮真实浏览器验收

只在独立副本/测试库操作。每节记录Python、OS、浏览器版本和起止时间；失败写步骤/预期/实际/截图，未复现也写清。AppTest、API故障注入与真实浏览器分别记录。本清单不是宣称已全量执行。

## A：升级

A-1：3a测试副本保留供应商、物料、订单及报价。升级仅app.py/db.py，不替换自己的配置或数据。启动两次，旧记录完整，仅新增reconciliation，不自动为旧订单生成对账行；旧四表结构、数据、唯一外键及无触发器由自动测试核对。

## B：保存与约束

B-1：API签名save_reconciliation(order_id, values)，定位参数独立。values传order_id/id/status等必须拒绝，原库不变。

B-2：打开未标记订单，三列为灰色未标记；不勾任何项直接保存，变为灰色未完成，DB建立一行。再次保存不增加行数；勾选再取消仍保留全0记录。

B-3：分别勾货、票、款，可以独立保存；款1而货票0也允许。发票号/付款日不必填；填入后保存，再清空发票号并点清空付款日期，保存后为NULL。

B-4/B-5：API验证非法布尔、真实日历日、发票类型及不存在订单可读拒绝；SQL直接验证order_id NOT NULL UNIQUE、外键、布尔和付款日期格式CHECK。正常页面不提供不存在订单ID输入框。

## C：全部8组合与三个筛选

C-1：独立创建以下9个测试订单：UNMARKED无对账记录；B000/B001/B010/B011/B100/B101/B110/B111分别按货票款三位保存。可由页面逐笔建立；自动测试另有同组固定数据。

| 筛选 | 应包含 |
|---|---|
| 全部 | 全部9单 |
| 货到未收票 | B100、B101 |
| 票到未付款 | B010、B110 |
| 三单未齐 | UNMARKED及除B111外全部组合 |

未标记与全0只进三单未齐；货1票0款0进货到未收票和三单未齐；B111不进三类。多个筛选可以重叠。

## D：状态与对账独立

D-1：记录订单状态、日期、数量/金额等全部值，新增/更新/取消对账后订单整行不变。比价记录也不变。

D-2：给一笔已下单订单保存对账记录并记录其全部字段。进入订单页实际点击“推进至：供应商已确认”；确认订单状态真的变化，再直接读取reconciliation整行，与推进前完全一致。不能用两次get_order代替对账行比对。状态区显示“对账标记不改变此处状态”。

## E：删除

E-1/E-2：保存两笔订单的对账行，进入其中一笔订单删除区，看到“该订单的对账记录将一并删除”；未勾原确认不能删除。勾确认后删除，订单及其对账行同时消失，另一笔订单/对账保留，无孤立记录。仅用于清理测试数据。

## F：事务与错误

F-1：自动故障注入模拟保存中SQL完整性失败，验证中文错误、目标与旁行回滚、后续合法保存成功。仅自动补充，不冒充自然浏览器错误复现。

F-2：自动SQL trace确认BEGIN IMMEDIATE和COMMIT，不含订单UPDATE。页面正常错误应有字段提示及保存按钮附近摘要，不能暴露原始IntegrityError。

## G：页面交互

G-1：列表仅订单号、供应商、物料快照、下单日期及货/票/款，不显示orders.status。无记录灰色未标记；已有0灰色未完成；1绿色✓。宽表可用默认全屏或列菜单查看。

G-2：新增/修改/取消与可选字段清空；筛选为空时详情仍可打开订单并保存，保存后满足筛选的行出现。对账页提示“对账标记不改变订单状态”。

G-3：自然UI无法构造非法日期时注明未验证自然错误路径；字段错误显示另由明确标注的自动注入覆盖。

G-4：独立空库无订单，对账页正常显示暂无订单，不出现保存按钮。

G-5：A保存货1/发票A/付款日2026-10-21，B保存票1/发票B/付款日空。A改货、发票、日期但不保存→B→A，应显示各自DB保存值，不串值；DB不变。即使未复现也记录具体观察值。

## H：持久化与范围

H-1：重启对账记录完整；复制整个目录含config/data到另一位置、重建venv后读取相同数据。自动补充db_path切换、缺目录自动创建及两个连接foreign_keys=1。

H-2：配置及state_machine.py不变；报价和仪表盘函数原文不变；仅新增reconciliation，不改旧四表结构，无其他新表/配置键/依赖。状态集中性AST与人工抽查、逐文件哈希及旧轮回归分别核对。
